UI foundation: MUI 9, shadcn/ui + Tailwind, or Mantine

Which component and styling foundation should the rewritten portfolio be built on? Migration effort doesn't count, because the app is being rebuilt. Versions were checked on npm today.

Recommendation shadcn/ui + Tailwind CSS v4, on Radix primitives

It is the only option where the three hard requirements are native rather than worked around: a bespoke visual identity, four mutually exclusive layout modes, and an AI surface that shares CopilotKit v2's own stack. Mantine 9 is a solid runner-up if you'd rather not own component code. MUI 9 is not recommended for the new app.

What decides it

Layout modes become part of the styling language

A Tailwind v4 custom variant turns the landscape rule into a class that can't be overridden by rule order, the root cause of today's bug. Mantine's and MUI's responsive props are width-only.

Same stack as CopilotKit v2

CopilotKit 1.73's v2 UI is built on Tailwind v4, Radix, cva, tailwind-merge and Lucide. We use its headless hooks either way, but can adapt its tool-call and suggestion components directly and share one token set.

No house style to fight

All three design directions are custom. With MUI, nearly every Material default gets overridden. With shadcn, the look is written once, in tokens and variants.

Zero-runtime CSS

Static CSS with no style injection at render supports the Lighthouse ≥ 90 mobile target. MUI 9 still requires Emotion at runtime.

Where Mantine wins

Coverage: Spotlight (⌘K), Timeline, charts, code highlighting and Carousel are ready-made. With shadcn, Timeline and CodeBlock are custom, but our designs need custom versions of both anyway.

The cost of shadcn

You own around 30 component files and their upgrades, and class strings can sprawl without discipline. Both are manageable with the guardrails below.

@custom-variant compact-landscape (@media (orientation: landscape) and (max-height: 500px));
@custom-variant tablet  (@media (min-width: 600px) and (max-width: 899.98px) and not ((orientation: landscape) and (max-height: 500px)));
@custom-variant desktop (@media (min-width: 900px) and not ((orientation: landscape) and (max-height: 500px)));

<div class="grid grid-cols-1 compact-landscape:grid-cols-2 tablet:grid-cols-2 desktop:grid-cols-3">

Guardrails that make shadcn safe

  1. Tokens only. tokens.css holds @theme plus the light and dark variable sets. Lint forbids arbitrary values like [#hex] or [13px] outside ui/.
  2. Variants, not class soup. Every reusable component defines its states with cva. Pages compose components; they don't style primitives.
  3. Own the upgrade path. Record the registry version in ui/README.md and review shadcn diff quarterly.
  4. Browser floor. Tailwind v4 targets Safari 16.4+, Chrome 111+ and Firefox 128+. Confirm that's acceptable (UF-2).
