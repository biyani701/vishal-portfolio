Primitive layer: Radix, Base UI or React Aria

Which headless library supplies behaviour, accessibility and focus management underneath our shadcn/ui components? The shadcn CLI supports all three via --base radix | base | aria. Facts were checked on npm and in package contents today.

Recommendation Base UI, plus React Aria's live announcer for AI answers

Base UI and React Aria come out close on the scorecard. The tie is broken by what we have to build: the mobile nav, the Ask sheet and ⌘K need a drawer and an autocomplete. Base UI ships both. React Aria has no drawer, and Radix relies on two libraries that haven't had a release in over a year. This reverses my earlier lean towards Radix; the reason is explained below.

Why Base UI

The drawer is on our critical path

The mobile nav, the Ask sheet and the compact-landscape drawer are exactly where the current site breaks. Base UI ships a drawer. With React Aria we'd build gestures and iOS scroll lock ourselves, and with Radix we'd rely on vaul, unreleased since Dec 2024.

⌘K without cmdk

Search and Ask share one command bar. Base UI's Autocomplete inside a Dialog covers it natively, while cmdk has had no release since March 2025.

The most active trajectory

Base UI went from 1.0 to 1.8 in nine months, and it's built by the people behind Radix and Floating UI.

Closing the accessibility gap

Use @react-aria/live-announcer (3.5.1) to announce streamed AI answers and tool status. That's the one area where React Aria is clearly ahead.

Why not Radix any more

My earlier lean rested on matching CopilotKit's stack. We use its headless hooks, so matching buys little, and CopilotKit's own Radix dependencies ship either way without conflict.

When React Aria is the better call

If a formal accessibility audit matters more than build effort, and you're willing to build and own the drawer yourself.

Making Base UI work well with Claude Code

  1. Source in the repo. shadcn copies each component into src/ui/, so Claude edits current code instead of recalling APIs.
  2. CLAUDE.md rules. Import from @base-ui/react 1.x, compose with render and never asChild, add primitives with shadcn add, and link the Base UI docs.
  3. Lint guards. Ban the old @base-ui-components/react name, plus @radix-ui/*, vaul and cmdk, in app code, and flag any asChild prop.
  4. Contract tests. Keyboard and focus tests for Dialog, Drawer, Menu, Autocomplete and Popover live in ui/ and run on every upgrade.
